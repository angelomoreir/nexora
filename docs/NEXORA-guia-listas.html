1. O que são Listas

Uma Lista no NEXORA é uma mini base de dados estruturada — o equivalente a uma lista do SharePoint ou a uma folha Excel com tipos de coluna fortes. Define-se um esquema de campos (colunas) e depois a equipa mantém registos (linhas) em conjunto: criar, editar, filtrar, ordenar, exportar.

Quando usar uma Lista: dados vivos que a equipa mantém continuamente — inventário, contactos, fornecedores, requisições, pipeline comercial, controlo de equipamento, registo de formações. Se precisa de recolher respostas de várias pessoas (uma submissão por pessoa), use Formulários em vez disso.

4. Criar e configurar uma lista — passo a passo

4.1 Criar (com ou sem template)

  1. Menu Listas → «Nova lista» — abre o seletor de modelos.
  2. Escolher «Em branco» ou um template: Clientes, Inventário, Contactos, Fornecedores, Requisições — o template nasce já com os campos preenchidos.
  3. Ajustar nome e descrição → Criar. Lista criada com os campos do modelo, pronta a receber registos.

4.2 Editar o esquema de campos

  1. Abrir a lista → modo de edição de campos.
  2. Adicionar campo: nome, slug (gerado automaticamente a partir do nome, editável), tipo, obrigatório, opções (se Escolha) ou lista de destino (se Relação).
  3. Reordenar com as setas; editar ou remover campos existentes.
  4. Guardar. Confirmação «Lista guardada»; erros de validação aparecem com mensagem traduzida.
Cuidado ao remover campos: registos existentes perdem os valores dessa coluna. Prefira renomear/reordenar quando possível.

4.3 Gerir registos

  1. «Novo registo» → preencher os campos → criar.
  2. Clicar numa linha → editar valores → guardar.
  3. Menu de linha → eliminar registo.
  4. Exportar CSV — descarrega todos os registos para Excel.
  5. Duplicar lista — cria uma cópia da estrutura (útil para variantes).

8. Boas práticas e resolução de problemas

  • Comece por um template — é mais rápido ajustar do que criar do zero.
  • Slugs estáveis: o slug identifica o campo nos dados/API — não o mude depois de ter registos.
  • Marque como obrigatório só o essencial — demasiados obrigatórios afastam quem regista.
  • Use «Escolha» em vez de texto livre para estados/categorias — evita «Ativo», «activo», «ATIVO».
  • Relações em vez de duplicar dados — o fornecedor existe uma vez, é referenciado em todo o lado.
