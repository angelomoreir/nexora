Guião de Testes Manuais — Passo a Passo

Âmbito: todas as funcionalidades da aplicação, todos os papéis de utilizador

Ambiente: desenvolvimento local · Web http://localhost:5173 · API http://localhost:3000/api/v1

Versão: 1.0 · Data: ____________ · Tester: ____________________

0. Como usar este guião

Execute os passos pela ordem indicada. Em cada passo, marque a caixa quando concluído e compare o resultado com o texto a verde. Quando o resultado não corresponder ao esperado, registe o defeito na tabela da Secção G (última página).

Passo a executar e marcar → Esperado: resultado correto → Esperado (negado): a ação deve ser recusada / invisível
Sugestão de ordem: 1) preparar ambiente → 2) site público e autenticação → 3) criar organização e os 5 utilizadores → 4) testes funcionais por módulo com o Admin → 5) repetir os pontos-chave com cada papel → 6) isolamento entre organizações.

1. Preparação do ambiente

  1. Abrir um terminal em D:\nexora e garantir que o PostgreSQL está a correr: docker compose up -d postgres (ou uma instância existente em DATABASE_URL).
  2. Arrancar a app: npm run dev. Dois processos sobem: API em http://localhost:3000/api/v1 e Web em http://localhost:5173.
  3. Confirmar o health check no browser: http://localhost:3000/api/v1/health. JSON com estado OK da base de dados e storage.
  4. (Opcional, recomendado) Povoar dados de demonstração: com a API a correr, executar node scripts/seed-demo.mjs. É criada a organização «XPTO, Lda.» com 5 utilizadores (um por papel), pastas, documento, lista «Clientes», projeto «Onboarding ABC», 3 tarefas, workflow «Aprovação de Despesas» publicado, equipa «Consultores», uma notícia e um convite pendente.

2. Site público (sem login)

  1. Abrir http://localhost:5173/ em sessão anónima. Landing page carrega com menu: Funcionalidades, Preços, Sobre, FAQ, Contacto.
  2. Percorrer /features, /pricing, /about, /faq, /contact. Todas as páginas renderizam sem erros; /pricing mostra os 5 planos (Free, Basic, Professional, Business, Enterprise) com preços mensal/anual.
  3. Abrir /terms e /privacy. Páginas legais carregam.
  4. Tentar abrir uma rota inexistente, ex.: /xyz. Redireciona para a landing page.
  5. Tentar abrir /dashboard sem sessão. Redireciona para /login.

3. Autenticação e ciclo de vida da conta

3.1 Registo de nova organização

  1. Em /register, submeter com password fraca (ex.: abc123). Erro de validação — a password exige mínimo 12 caracteres, maiúscula, minúscula e número.
  2. Registar: Nome Teste Admin, Organização Empresa Teste Lda, email único, password válida (ex.: Teste12345! → tem 12+? use TesteSegura123). Conta criada e sessão iniciada; entra como Admin da nova organização; plano Free atribuído; pastas «Documentos → Contratos, Faturas, Projetos» já existem em Documentos.
  3. Registar outro utilizador com o mesmo email. Recusado com erro de email já existente.

3.2 Login / logout / erros

  1. Terminar sessão pelo menu do avatar → Sair. Volta a /login; rotas internas deixam de abrir.
  2. Login com password errada. Mensagem de credenciais inválidas (sem revelar se o email existe).
  3. Repetir login errado várias vezes seguidas (5+). Rate limiting entra em ação (HTTP 429 / mensagem de bloqueio temporário).
  4. Login correto. Entra e cai no Dashboard / O meu dia.
  5. No login, clicar «Continuar com SSO» com um email de domínio sem SSO. Mensagem «Não existe SSO configurado para este domínio de email.»

3.3 Recuperação de password

  1. Em /forgot-password, submeter um email existente. Confirmação genérica «Instruções enviadas». Em dev (EXPOSE_PASSWORD_RESET_TOKEN=true) aparece «Abrir ligação de desenvolvimento».
  2. Abrir a ligação de desenvolvimento → definir nova password válida. Password atualizada; consegue entrar com a nova password.
  3. Reutilizar a mesma ligação de reset. Ligação inválida — só pode ser usada uma vez.
  4. Pedir reset para email inexistente. Mesma mensagem genérica (não revela se a conta existe).

4. Criar todos os tipos de utilizador (como Admin)

Em Administração → Utilizadores (ou em Configurações), criar um utilizador por papel. Se usou o seed, estas contas já existem — mesmo assim valide o fluxo de convite.

  1. «Adicionar utilizador»: criar Manager Teste com papel Manager e password inicial válida. Aparece na lista com a função Manager.
  2. Repetir para Editor, Member e Viewer. Os 4 utilizadores aparecem na lista.
  3. Criar utilizador com password com < 12 caracteres. Validação impede a submissão.
  4. Convite por email: «Convidar utilizador» com um email novo e papel Viewer. Convite criado; aparece em «Convites pendentes» com estado Pendente e data de expiração. Sem SMTP configurado, a app mostra a ligação de convite para copiar.
  5. Copiar a ligação e abrir /accept-invite?token=… em janela anónima → aceitar e definir password. Conta criada/iniciada; o convite passa a «Aceite»; o utilizador entra na organização.
  6. Reabrir a mesma ligação de convite. «Convite inválido» — já utilizado.
  7. Criar novo convite e depois «Revogar» antes de ser aceite → abrir a ligação. Convite inválido/revogado.
  8. Iniciar sessão com cada um dos 5 utilizadores criados e confirmar que entram. Todos autenticam; o menu lateral adapta-se ao papel (ver Secção 5).

5. Matriz de papéis — o que cada um deve (e não deve) conseguir

Para cada papel, iniciar sessão e verificar o menu lateral e as ações. Dica: use janelas de browser separadas ou perfis diferentes para manter várias sessões em simultâneo.

5.1 Viewer (só leitura) — eduardo@xpto.pt

  1. Menu lateral: Vê O meu dia, Dashboard, Pesquisa, Tarefas, Aprovações, Processos, Notificações, Sites, Notícias, Documentos, Listas, Formulários, IA, Ajuda, Planos, Configurações, Perfil. Não vê «Análise» nem «Administração».
  2. Documentos: tentar «Nova pasta» / «Upload». Ações de escrita indisponíveis ou recusadas (403).
  3. Tarefas: tentar «Nova tarefa». Recusado.
  4. Listas e Formulários: abrir e consultar registos. Lê tudo; botões de criar/editar ausentes ou recusados.
  5. Processos: abrir um workflow. Vê o desenho; não consegue editar nem iniciar.
  6. Aprovações: vê a fila. Consulta; não decide — salvo se for o aprovador designado (a decisão é por atribuição, não por permissão).

5.2 Member — carla@xpto.pt

  1. Menu: igual ao Viewer, sem «Análise» e «Administração». Confirma-se.
  2. Criar uma tarefa e marcar como concluída. Permitido.
  3. Fazer upload de um documento e editar metadados. Permitido (documents.edit).
  4. Tentar eliminar um documento e partilhar um documento. Ambos recusados — Member não tem documents.delete nem documents.share.
  5. Tentar criar Lista / Formulário / Processo / Site / Notícia. Tudo recusado (só view nestes módulos).
  6. Aprovar/rejeitar uma aprovação atribuída a si. Permitido (approvals.manage).
  7. Abrir /admin e /analytics diretamente pelo URL. Redirecionado para o dashboard / acesso negado.

5.3 Editor — diana@xpto.pt

  1. Menu: Aparece «Administração» (tem users.update e webhooks.manage), mas não «Análise».
  2. Criar lista, formulário, processo, notícia e página de site. Permitido (manage nesses módulos).
  3. Eliminar documento. Permitido (documents.delete).
  4. Partilhar documento / criar link público. Recusado (sem documents.share).
  5. Criar site (não só páginas). Permitido — Editor tem sites.manage.
  6. Em Administração: abrir Auditoria e Definições da organização. Sem audit.view nem settings.manage — cartões ocultos no painel e dados recusados por URL direto.
  7. Tentar criar utilizador ou mudar o papel de alguém. Recusado (users.create / roles.manage ausentes); users.update só permite suspender/reativar membros — não edita perfis de terceiros nem papéis.
  8. Criar um webhook em Administração → Webhooks. Permitido (webhooks.manage).

5.4 Manager — bruno@xpto.pt

  1. Menu: Vê «Análise» e «Administração».
  2. Criar utilizador com papel Member. Permitido — é o único papel que pode atribuir (a API exige roles.manage para qualquer outro papel).
  3. Criar utilizador com papel Viewer/Editor/Admin. Recusado — a API exige roles.manage para papéis que não Member; a interface só oferece «Member» a quem não tem roles.manage.
  4. Mudar o papel de um membro existente. Recusado (roles.manage é só do Admin).
  5. Eliminar um utilizador. Recusado (users.delete é só do Admin).
  6. Suspender/reativar membro (estado na organização). Permitido (users.update). Editar nome/cargo/avatar de outro utilizador: recusado — os campos de perfil globais só podem ser alterados pelo próprio ou pelo Super Admin.
  7. Abrir Auditoria, Definições da org, Webhooks, Automatização, Governance, Anúncios. Tudo acessível.
  8. Criar função personalizada em Funções. Recusado (roles.manage).

5.5 Admin — ana@xpto.pt

  1. Confirmar acesso a tudo o que foi negado acima: eliminar utilizador, criar/editar funções personalizadas, mudar papéis, criar Admins, gerir definições e SSO. Todas permitidas — exceto editar o perfil (nome/cargo/avatar) de outro utilizador, que é exclusivo do próprio ou do Super Admin.
  2. Tentar editar uma «Função de sistema» (Admin, Manager…). Protegida — «As funções de sistema não podem ser editadas.» (a API também recusa).
  3. Remover-se a si próprio da organização. A interface não oferece a opção e a API recusa (400 — não pode remover-se a si próprio).

6. Testes funcionais por módulo (executar como Admin, salvo indicação)

6.1 O meu dia, Dashboard e Pesquisa

  1. Abrir «O meu dia». Saudação conforme a hora; contadores «Para hoje», «Em atraso», «Aprovações pendentes», «Por ler»; secções Foco de hoje / Próximas tarefas / Decisões pendentes / Atualizações por ler.
  2. Num cartão de tarefa, clicar «Iniciar» e depois «Concluir». O estado da tarefa muda sem sair da página.
  3. Botão «Atualizar». Recarrega os dados.
  4. Dashboard: criar «Novo dashboard», renomear, alternar entre dashboards, ver widgets e anúncios. Dashboards persistem e refletem dados da organização.
  5. Pesquisa (/search): pesquisar «ABC». Resultados agrupados por tipo (documentos, registos da lista Clientes, tarefas…); filtros por tipo funcionam; clicar num resultado navega para o item.
  6. Pesquisar um termo do conteúdo de um ficheiro de texto enviado. O documento aparece (pesquisa full-text em txt/CSV/PDF/Word).
  7. Pressionar Ctrl+K. Abre a pesquisa universal: comandos de navegação + resultados; setas navegam, Enter abre.

6.2 Documentos — estrutura e ficheiros

  1. Em Documentos, criar pasta «Testes» e dentro dela «Subpasta». Hierarquia criada; breadcrumb navega.
  2. «Upload» de um ficheiro (ex.: PDF ou TXT) para a subpasta. Ficheiro aparece com tipo, tamanho, proprietário e data.
  3. Arrastar um ficheiro para a lista (drag & drop). Overlay «Largue para enviar»; fila de envio mostra progresso e conclui.
  4. Alternar vista Lista/Grelha; ordenar por Nome, Modificado, Tamanho, Tipo; pesquisar na pasta; filtros Todos/Documentos/Pastas/Favoritos. Tudo reage corretamente.
  5. Vistas rápidas: Recentes, Favoritos, Partilhado comigo, Todos. Cada vista filtra como descrito.
  6. Marcar documento como Favorito e «Fixar no topo». Aparece em Favoritos e fica pinado na lista.
  7. Renomear, Mover e Copiar o documento entre pastas. Operações concluídas; cópia criada no destino.
  8. Selecionar vários itens (checkbox) → ações em massa: mover e eliminar. Operações aplicadas a todos os selecionados.

6.3 Documentos — detalhe, versões e colaboração

  1. Abrir o detalhe do documento. Separadores Detalhes/Versões/Comentários/Atividade; pré-visualização se o formato suportar (senão «Descarregar para visualizar»).
  2. «Enviar nova versão» (ficheiro alterado) como versão Principal e depois como Secundária (rascunho). Histórico mostra as duas; a secundária fica como rascunho/pendente.
  3. «Restaurar versão» antiga e «Descarregar versão». Versão restaurada passa a atual; download funciona.
  4. «Check-out» do documento; com outro utilizador tentar editar/enviar versão. Bloqueado — «em check-out por {nome}». Como Admin, «Forçar check-in» liberta o documento.
  5. Adicionar comentário com menção «@Nome». Comentário registado; o mencionado recebe notificação.
  6. «Sugerir metadados com IA». Campos sugeridos marcados com selo IA (requer provider configurado).
  7. «Alertar-me» (subscrição). Alerta ativo; uma alteração posterior gera notificação.
  8. Ver separador Atividade. Regista visualizações, transferências e edições.

6.4 Documentos — partilha, acesso e governança

  1. «Partilhar» → com utilizador (Viewer), com equipa e com a organização, com níveis Leitura/Edição. Os destinos passam a ver o item em «Partilhado comigo» com a permissão certa.
  2. «Criar link» público com validade (ex.: 24h) e password. Abrir /share/{token} em janela anónima. Pede a password; após password correta permite ver/descarregar.
  3. Link com permissão de edição → «Enviar nova versão» via link público. Nova versão registada na atividade como «Nova versão via link».
  4. Revogar o link e reabrir o URL. «Link indisponível».
  5. Numa pasta, criar link de «Pedido de ficheiros». Quem abre o link pode enviar ficheiros mas não vê o conteúdo da pasta.
  6. «Gerir acesso»: ver quem tem acesso e a origem (proprietário/utilizador/equipa/ligação); desligar «Herdar permissões». Com herança desligada, quem só tinha acesso por herança deixa de ver o item.
  7. Como utilizador sem acesso, abrir o URL direto do documento → «Pedir acesso» com mensagem. Como proprietário, aprovar em «Pedidos de acesso». Pedido enviado → aprovado → o utilizador ganha acesso e recebe notificação.
  8. «Governança» na pasta: definir Sensibilidade = Confidencial. A criação de links públicos fica bloqueada nessa pasta e descendentes.
  9. Sensibilidade = Restrito. Também bloqueia partilha com toda a organização.
  10. Retenção = «Bloquear eliminação» → tentar eliminar item dentro. Bloqueado pela política de retenção.
  11. «Exigir aprovação de conteúdo» numa pasta → enviar nova versão. Versão fica «Pendente»; só após «Aprovar» é publicada; «Recusar» marca como recusada.
  12. «Declarar como registo» e «Aplicar retenção legal» num documento. Badges «Registo»/«Retenção legal»; o registo fica imutável e não pode ser eliminado.
  13. «Campos de metadados» numa pasta: adicionar campos; abrir documento numa subpasta. Subpastas herdam os campos; documento permite preenchê-los.
  14. «Marcar como modelo» um documento/pasta → «Novo a partir de modelo». Cria cópia a partir do modelo na pasta atual.

6.5 Reciclagem

  1. Eliminar um documento e uma pasta. São movidos para a reciclagem (não apagados já).
  2. Abrir Documentos → Reciclagem. Itens com localização original, «Eliminado por» e data.
  3. «Restaurar» um item. Volta à pasta original.
  4. «Eliminar definitivamente» um item. Removido para sempre após confirmação.
  5. «Esvaziar reciclagem». Tudo eliminado definitivamente (ação não anulável).

6.6 Listas

  1. Criar lista «Fornecedores». No Construtor adicionar campos de vários tipos: Texto (obrigatório), Número, Moeda, Data, Escolha (com opções), Email, Boolean. Campos criados e reordenáveis (mover para cima/baixo).
  2. Separador Dados → «Novo registo» com campo obrigatório vazio. Validação «é obrigatório».
  3. Criar 3 registos válidos; editar um; pesquisar registos; selecionar 2 → «Eliminar (2)». CRUD, pesquisa e eliminação em massa funcionam.
  4. «Exportar CSV». Ficheiro descarregado com os registos.
  5. «Duplicar» a lista. Cópia criada com a mesma estrutura.
  6. Como Member/Viewer: tentar criar lista ou registo. Recusado (só leitura).

6.7 Formulários

  1. «Novo formulário» → abrir no Construtor → adicionar componentes: Título, Texto, Email (obrigatório), Seleção, Rádio, Checkbox, Upload, Separador. Componentes adicionados com etiqueta, placeholder, obrigatório e opções configuráveis.
  2. Modo «Pré-visualização». Aviso de que não está publicado; pré-visualiza o formulário.
  3. «Publicar» → submeter uma resposta válida e uma inválida (sem email obrigatório). Válida aceite; inválida bloqueada por validação.
  4. Separador «Respostas»: ver submissões e «Exportar CSV». Submissões listadas com data e autor; CSV correto.
  5. «Arquivar» → tentar submeter. Não aceita novas respostas. «Reativar» repõe.
  6. «Duplicar» e «Eliminar» formulário. Ambos funcionam com confirmação.

6.8 Tarefas e projetos

  1. Criar projeto «Projeto Teste» (com cor). Projeto criado e selecionável nas tarefas.
  2. «Nova tarefa»: título, descrição, prioridade Urgente, responsável (Member), data limite amanhã, etiquetas «teste, cliente», associar projeto. Tarefa criada; o responsável recebe notificação «Tarefa atribuída».
  3. Vistas Lista / Kanban / Calendário. Kanban agrupa por estado (A fazer, Em curso, Em revisão, Concluída, Cancelada) e permite mover; calendário mostra a tarefa no dia do prazo.
  4. Abrir o detalhe da tarefa: editar estado/prioridade/responsável, adicionar comentário. Alterações guardadas; comentários contados.
  5. Como Member (responsável): mudar a tarefa para Concluída. Permitido.
  6. Como Viewer: tentar criar tarefa. Recusado.
  7. Pesquisar/filtrar tarefas por texto, estado e responsável. Filtros aplicados corretamente.

6.9 Processos (workflows)

  1. «Novo processo» «Teste Aprovação» → abrir o Construtor. Criado como Rascunho com passos Início/Fim por defeito.
  2. Na paleta, adicionar passos: Aprovação (definir aprovador = Manager), Enviar notificação, Criar tarefa, Condição (com salto para passo). Passos adicionados, reordenáveis/arrastáveis, duplicáveis; configuração por passo (aprovador, título da notificação, operador, valor de comparação…).
  3. Tentar publicar sem passo Fim no fim / sem nome num passo. Painel de validação «O fluxo precisa de atenção» lista os problemas.
  4. Corrigir e «Guardar processo» → «Publicar». Estado Publicado; o construtor fica bloqueado para edição.
  5. «Iniciar processo» com dados de entrada JSON (ex.: {"valor": 250}). Instância criada «Em execução»; passo de aprovação fica a aguardar; o aprovador recebe notificação.
  6. Como aprovador, abrir a instância → «Aprovar» com comentário. Passo concluído; processo avança; notificação enviada; tarefa criada pelo passo correspondente; instância «Concluída».
  7. Nova instância → «Rejeitar» no passo de aprovação. Respeita o «Em rejeição, saltar para o passo #» se configurado; estado coerente.
  8. Ver «Instâncias» no detalhe do processo: progresso «X de Y passos concluídos», detalhes e resultado de cada execução. Histórico completo.
  9. «Arquivar» o processo → tentar iniciar. Não inicia. «Reativar» repõe.
  10. Como Editor: editar/criar processo. Permitido. Como Member/Viewer: só consulta (mensagem de sem permissão no builder).

6.10 Aprovações

  1. Separadores Minhas/Todas; filtros Pendentes/Aprovadas/Rejeitadas. A fila reflete as aprovações do processo de 6.9.
  2. Abrir uma pendente: ver pedido, recurso, histórico; «Aprovar» e «Rejeitar» com nota de decisão. Decisão registada com data e autor; pedido original recebe notificação.
  3. «Delegar» uma aprovação noutro membro. Estado «Delegada»; passa a constar na fila do delegado, que pode decidir.
  4. Adicionar comentário a uma aprovação. Comentário fica registado no histórico.
  5. Como Viewer: ver a fila. Só consulta — sem botões de decisão.

6.11 Notificações

  1. Sino no topo com contador. Badge mostra nº de não lidas (9+ se mais de 9); atualiza em tempo real quando chega notificação nova.
  2. Página Notificações: separadores Todas/Não lidas; «Marcar como lida» numa; «Marcar todas como lidas». Estados atualizam e o badge desce.
  3. Verificar que os eventos anteriores geraram os tipos certos: tarefa atribuída, menção, aprovação pendente, decisão, processo concluído, documento partilhado/alterado/comentado, pedido de acesso. Cada tipo tem texto/ícone próprio.

6.12 Análise (Admin/Manager)

  1. Abrir «Análise» e alternar período 7/30/90 dias. KPIs atualizam: tarefas criadas/concluídas, taxa de conclusão, em atraso, documentos criados, utilizadores ativos, tempo médio de aprovação, taxa de sucesso de workflows.
  2. Verificar gráficos: Atividade diária, Tarefas por estado, Aprovações, Desempenho de workflows, Adoção. Refletem a atividade gerada nos testes anteriores.
  3. Como Editor/Member/Viewer abrir /analytics diretamente. «Análises indisponíveis» / sem permissão.

6.13 Sites e páginas

  1. «Criar site»: nome, tipo Departamento, visibilidade «Toda a organização», cor. Site criado; badge «O meu papel: Administrador».
  2. Dentro do site: criar sub-site (tipo Projeto, privado) e uma página; publicar a página e defini-la como inicial. Separador Início mostra a página; Conteúdo lista páginas com estado Rascunho/Publicada.
  3. «Adicionar membro» ao site com papel Contribuidor e outro Leitor. Membros listados com papéis de site (independentes do papel global).
  4. Site privado: como utilizador não-membro, tentar abrir o URL do site. Sem acesso / não listado.
  5. «Zona de perigo» → Eliminar site (num site de teste). Confirmação e remoção com conteúdos associados.
  6. Como Editor: criar site. Permitido (sites.manage). Como Member/Viewer: recusado (só sites.view).

6.14 Notícias

  1. «Nova notícia»: título, resumo, corpo, categoria, etiquetas, cor de capa, Destaque, estado Publicada. Publicada no feed; destaque visível.
  2. Notícia com estado Rascunho e outra Agendada. Estados corretos; rascunho não aparece como publicada para outros.
  3. Associar notícia a um site (vs. global). Aparece no contexto do site.
  4. Abrir a notícia → comentar como outro utilizador. Comentários contados e visíveis.
  5. Como Member/Viewer: criar notícia. Recusado (só news.view).

6.15 Assistente IA

  1. Abrir «Assistente IA» → «Nova conversa». Ecrã «Como posso ajudar?» com sugestões e indicação «Respeita as suas permissões».
  2. Clicar numa sugestão (ex.: «Quais são as tarefas atrasadas?»). Resposta baseada nos dados reais da organização.
  3. Pedir «Que documentos tenho sobre o cliente X?». Resposta só refere documentos a que tem acesso.
  4. Pedir «Cria uma lista de Clientes com Nome, NIF, Email, Telefone e Estado». Proposta com prévia (nº de campos) → «Confirmar» → lista criada e visível em Listas.
  5. Pedir «Cria um processo para aprovar despesas superiores a 1.000 euros». Prévia com nº de passos → confirmar → workflow criado como rascunho em Processos.
  6. Pedir uma aplicação completa (lista+formulário+workflow+página) e escolher site de destino. Estrutura criada; página publicada no site escolhido.
  7. Ver painel «Utilização hoje» (pedidos/tokens/custo) e «Limpar conversa». Métricas e limpeza funcionam.
  8. Como Viewer: pedir para criar algo. A IA não executa ações que o papel não permite.

6.16 Central de Ajuda

  1. Abrir «Central de Ajuda»: navegar categorias e artigos, usar a pesquisa de ajuda e o assistente. Conteúdo carrega; pesquisa devolve artigos.
  2. Botão de ajuda contextual (ícone ?) numa página, ex.: Documentos. Abre ajuda relativa a essa página.

6.17 Administração

  1. Painel Admin: cartões Utilizadores, Equipas, Funções, Auditoria, Segurança, Webhooks, Automatização, Governance, Anúncios, Definições. Todos navegam para a respetiva página.
  2. Utilizadores: suspender um membro → esse utilizador tenta entrar. Login recusado enquanto suspenso. Reativar repõe o acesso.
  3. Equipas: criar equipa, adicionar/remover membros, eliminar equipa de teste. Equipas usáveis na partilha de documentos e atribuições.
  4. Funções: criar função personalizada com um subconjunto de permissões (ex.: só documents.view + tasks.view), atribuí-la a um utilizador e entrar com ele. O utilizador fica limitado exatamente a esse subconjunto.
  5. Auditoria: pesquisar e filtrar por ação, tipo de recurso e resultado. Registos das ações feitas nos testes (criações, logins, alterações de definições) com ator, IP, data e resultado.
  6. Segurança: ver estado do SSO, política de passwords, membros suspensos, sessões ativas e eventos de segurança (logins falhados dos testes 3.2 devem aparecer). Painel coerente com os testes feitos.
  7. Definições → Geral: alterar URL do logo, idioma e fuso horário da organização → guardar. Logo aplicado no menu; definições persistem após reload.
  8. Definições → Segurança: aumentar «Comprimento mínimo da password» e ativar «Exigir símbolo» → criar utilizador com password simples. A nova política é aplicada. Repor valores depois.
  9. Definições → SSO: preencher Issuer URL, Client ID, Secret e domínio de email → ativar. Configuração guardada; o login passa a oferecer SSO para esse domínio (o fluxo completo exige IdP real — sem IdP, validar apenas a configuração e o redirecionamento).
  10. Webhooks: criar webhook (nome, URL de endpoint, eventos) → copiar o segredo de assinatura (mostrado uma só vez) → «Testar» e ver «Entregas». Webhook criado; teste regista entrega (falha se o endpoint não existir — verificar que a falha é registada, não que a app crasha).
  11. Automatização: criar trigger «Quando um documento é criado → executar processo publicado» numa pasta; depois criar documento nessa pasta. O processo inicia automaticamente (nova instância visível).
  12. Automatização → Ações rápidas: criar ação para documentos → executá-la a partir do menu de um documento. «Ação iniciada» e workflow executado para o item.
  13. Governance: relatórios de ligações públicas ativas, documentos inativos, ficheiros duplicados, registos e retenções legais. Refletem o que criou nos testes 6.4 (links, registos, holds) e duplicados se enviou o mesmo ficheiro duas vezes.
  14. Anúncios: criar anúncio com público «Todos» e datas de publicação/expiração; outro com público «Equipa». Anúncios aparecem no dashboard dos utilizadores abrangidos e expiram na data definida.

6.18 Planos e faturação

  1. Abrir «Planos e Faturação». Plano atual (Free) e medidores de utilização: utilizadores, armazenamento, documentos, workflows, IA/mês.
  2. Alternar faturação mensal/anual. Preços atualizam (anual = 2 meses grátis).
  3. «Selecionar» noutro plano. Inicia checkout Stripe se configurado; caso contrário erro tratado («Não foi possível iniciar o checkout»), sem crash.
  4. Teste de limite: com plano Free (5 utilizadores / 1 GB / 100 documentos), tentar exceder o limite de utilizadores convidando o 6.º. «Limite atingido» com sugestão de upgrade.
  5. «Cancelar subscrição» e «Gerir pagamento». Pedem confirmação / comportam-se conforme o provider configurado (no-op em dev sem Stripe).

6.19 Perfil, tema e idioma

  1. Perfil: alterar nome, cargo e URL do avatar → guardar. Avatar/nome atualizam no topo e nas listas de utilizadores.
  2. «Alterar password» com a atual correta. Sucesso; todas as sessões terminadas → volta ao login e entra com a nova password.
  3. Com 2 sessões abertas (browsers diferentes), em Perfil → Sessões ativas → «Terminar» a outra sessão. A outra sessão deixa de funcionar; a atual continua.
  4. Alternar tema claro/escuro/sistema. Tema aplica-se de imediato e persiste.
  5. Mudar idioma da interface (EN, ES, FR, DE, PT). Interface traduzida por completo; datas/números formatados no locale.
  6. Se pertencer a 2 organizações: usar o seletor de organização no topo para alternar. Todos os dados mudam para a org selecionada.

7. Isolamento multi-tenant e casos limite

  1. Registar uma segunda organização (conta nova) e criar lá um documento «Segredo Org2». Dados totalmente separados.
  2. Com a sessão da Org1, tentar abrir o URL/ID do documento da Org2. Sem acesso / não encontrado — nenhum dado vaza entre tenants, nem via pesquisa nem via IA.
  3. Upload de ficheiro com tipo não permitido ou acima do tamanho máximo. Recusado com mensagem clara.
  4. Upload de ficheiro com extensão falsa (ex.: .txt renomeado para .pdf). Validação por magic bytes recusa.
  5. Exportar CSV de uma lista com campo a começar por «=» (ex.: =1+1). CSV sanitizado contra formula injection.
  6. Sessão inativa/expirada: deixar o token expirar e continuar a navegar. Refresh token renova em silêncio; quando expira de vez, volta ao login.
  7. Com a app offline (parar a API), usar o menu. Mensagens de erro amigáveis («verifique a ligação»), sem ecrãs partidos.
  8. Testar em janela estreita / telemóvel (responsive). Menu lateral colapsa em hamburger; tabelas e modais utilizáveis.
