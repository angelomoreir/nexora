1. O que são Processos

Um Processo (na API: workflow) é uma sequência de passos automatizada que corre dentro da organização — o motor de automação do NEXORA. Desenha-se uma cadeia de ações no construtor visual, publica-se, e cada execução (instância) percorre os passos sozinha: cria tarefas, pede aprovações, envia notificações e emails, move documentos — sem intervenção manual.

Diferença chave: Tarefas, Listas e Documentos guardam dados; Processos executam lógica — ligam todos os módulos numa sequência automática e auditável.

2. Conceitos fundamentais

ConceitoO que é
ProcessoA definição: nome, descrição e a sequência de passos
PassoUma ação do fluxo — com tipo, nome e configuração própria
Instância / ExecuçãoUma corrida concreta do processo, com contexto e histórico passo a passo
ContextoAs variáveis da execução — o JSON passado ao iniciar + o que os passos vão produzindo (ex.: context.taskId)
VariáveisEm qualquer campo de configuração, {{nome}} é substituído pelo valor do contexto — ex.: {{documentId}}
SaltoDesvio do fluxo linear: condições e rejeições podem saltar para outro passo

3. Ciclo de vida do processo

EstadoSignificado
RascunhoEm construção — o construtor está editável; não pode ser iniciado
PublicadoPronto a executar — validado pela API; o construtor fica bloqueado
ArquivadoRetirado de uso — mantém o histórico das execuções
Corrigir um processo publicado: na página do processo → «Retirar publicação» → volta a Rascunho → editar no Construtor → Guardar → Publicar de novo.

4. Tipos de passo

CategoriaPassoO que faz / configuração
ControloIniciar (START)Entrada obrigatória — todo o processo começa aqui
CondiçãoAvalia uma variável do contexto (variável + operador + valor); se verdadeira, salta para o passo configurado — senão segue em frente
Terminar (END)Saída obrigatória — marca a execução como concluída
TrabalhoCriar tarefaGera uma tarefa (título, descrição, responsável, prioridade, prazo) — guarda o id em context.taskId
AprovaçãoPára a execução até o aprovador designado decidir; configura aprovador, título/mensagem e salto de rejeição (para onde ir se rejeitado)
ComunicaçãoEnviar notificaçãoNotificação in-app a um membro (destinatário, título, corpo)
Enviar emailEmail real (destinatário, assunto, corpo) — exige SMTP configurado
DadosAlterar estadoMuda o estado da instância ou de um recurso (ex.: fechar a tarefa criada antes)
Atribuir utilizadorAtribui a execução/recurso a um membro
Alterar campoModifica um campo/dado
Mover documentoMove um documento para outra pasta (documento + pasta de destino — aceita {{variável}})

5. Criar e executar — passo a passo

5.1 Criar (com templates)

  1. Processos → «Novo processo» → seletor de templates: Aprovação de tarefa, Pedido de compra, Onboarding de membro, Aprovação de documento, Resposta a incidente — ou «Em branco» (START + END).
  2. O template cria a sequência completa de passos — os IDs de pessoas/documentos vêm como placeholders por preencher.

5.2 Construir

  1. Abrir o Construtor — paleta de passos à esquerda, fluxo à direita.
  2. Clicar num passo → configurar (aprovador, destinatário, título, IDs, variável da condição, salto…).
  3. O aviso amarelo de validação lista o que falta — o botão Guardar só ativa quando não há problemas.
  4. «Alterações por guardar» avisa antes de sair sem gravar; «Repor alterações» descarta a edição.

5.3 Publicar e executar

  1. «Publicar» — a API valida: começa em Iniciar, acaba em Terminar, passos ordenados, configuração obrigatória preenchida, saltos válidos.
  2. «Iniciar» → diálogo de dados de entrada em JSON — o que escrever vira o contexto (ex.: {"documentId": "abc"}, {"valorAlto": "true"}). Vazio ({}) usa só os valores fixos do construtor.
  3. A instância corre passo a passo — nas «Aprovações» pára até à decisão.

5.4 Acompanhar

  1. Separador «Instâncias» na página do processo: cada execução com estado (em execução, a aguardar aprovação, concluída, falhada).
  2. Expandir → histórico passo a passo: o que correu, resultado, erros.
  3. Erros de configuração (ex.: ID de documento inexistente) falham a instância com a mensagem do passo que falhou.

6. Exemplos práticos

Exemplo 1 — Aprovação de documento

Iniciar → Aprovação (gestor) → Mover documento para «Aprovados» → Notificar autor → Fim.
Aprovado: o documento muda de pasta e o autor é notificado. Rejeitado: salta direto para o Fim. Com {{documentId}} no passo de mover, cada execução trata o documento indicado nos dados de entrada.

Exemplo 2 — Pedido de compra com ramificação

Iniciar → Criar tarefa → Aprovação do gestor → Condição (valorAlto = "true"?) → [salta para] Aprovação da direção → Notificar → Fechar tarefa → Fim.
Valores baixos saltam a aprovação extra; valores altos passam por dois níveis de aprovação.

Exemplo 3 — Onboarding de membro

Iniciar → Criar tarefa «preparar acessos» → Email de boas-vindas → Notificar equipa → Fim.
Um clique em «Iniciar» executa o onboarding inteiro.

8. Boas práticas e resolução de problemas

  • Use templates — a parte difícil é a estrutura; ajuste os placeholders aos seus IDs reais.
  • Variáveis em vez de IDs fixos — {{documentId}} torna o processo reutilizável.
  • Nomeie os passos — «Aprovação do gestor financeiro» > «Aprovação».
  • Sempre configure o salto de rejeição nas aprovações — decida o que acontece quando é rejeitado.
  • Email precisa de SMTP — sem configuração, o passo de email falha a execução.
SintomaCausa provável
«Guardar» desativado no construtorValidação com problemas — ver o aviso amarelo
«Publicar» falhaEstrutura inválida — tem de começar em Iniciar e acabar em Terminar, campos obrigatórios preenchidos
Instância falhou a meioErro num passo — ex.: documento inexistente, SMTP em falta; ver o histórico da instância
Sem botão «Iniciar»Processo não está Publicado (ou falta workflows.manage)
