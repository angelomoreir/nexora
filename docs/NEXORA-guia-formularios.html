1. O que são Formulários

Um Formulário é uma ferramenta de recolha de dados — o equivalente interno a um Google Forms. Quem gere constrói o questionário, publica-o, e os membros da organização respondem — cada pessoa com a sua submissão. As respostas ficam reunidas numa tabela consultável e exportável.

Quando usar: pedidos de férias, inscrições em eventos, questionários de satisfação, registo de ocorrências, requisições, avaliações — sempre que várias pessoas submetem informação de forma estruturada.

2. Ciclo de vida — os 3 estados

EstadoO que significaQuem pode responder
Rascunho (DRAFT)Em construção — estado inicialNinguém
Publicado (PUBLISHED)Aberto a respostasTodos os membros da organização
Arquivado (ARCHIVED)Fechado — não aceita novas respostas (reativável)Ninguém
Regras importantes: (1) a API rejeita submissões de formulários não publicados; (2) não é possível publicar um formulário sem campos — precisa de pelo menos um campo de dados (além de títulos/separadores decorativos); (3) as respostas são internas — não existe link público externo.

4. Fluxo completo — passo a passo

4.1 Criar

  1. Formulários → «Novo formulário» → abre o seletor de modelos.
  2. Escolher «Em branco» ou um template: Pedido de férias, Questionário de satisfação, Registo de ocorrência, Inscrição em evento, Pedido de contacto.
  3. Ajustar nome/descrição → Criar. Nasce em Rascunho.

4.2 Construir (Builder)

  1. Abrir o formulário → «Construtor».
  2. «+ Adicionar campo» → escolher tipo → configurar etiqueta, obrigatoriedade, opções.
  3. Reordenar com setas; usar Títulos e Separadores para organizar formulários longos.
  4. Guardar — confirmação «Formulário guardado».

4.3 Publicar e recolher

  1. Na página do formulário → «Publicar». Estado passa a Publicado; membros já podem responder.
  2. Os respondentes abrem Formulários → nome, preenchem e submetem.
  3. Na página do formulário, o separador de respostas mostra cada submissão com autor e data; «Exportar CSV» descarrega tudo.

4.4 Fechar e reutilizar

  1. «Arquivar» — fecha a novas respostas (as existentes ficam consultáveis). Reativável depois.
  2. «Duplicar» — copia a estrutura para um novo formulário (questionários recorrentes).
  3. Eliminar — remove o formulário e as respostas.

5. Exemplos práticos

Exemplo 1 — Pedido de férias (template)
  • Texto: Nome do colaborador (obrigatório)
  • Data: Data de início · Data: Data de fim (ambas obrigatórias)
  • Escolha única: Tipo — Férias / Licença / Outro
  • Texto longo: Observações

Publicar → cada membro submete o seu pedido → RH exporta CSV no fim do mês.

Exemplo 2 — Questionário de satisfação
  • Número: Avaliação geral (1–5)
  • Texto longo: O que mais gostou? · Texto longo: Sugestões de melhoria

Arquivar quando terminar o período de resposta → analisar o CSV.

Exemplo 3 — Registo de ocorrências
  • Texto: Título da ocorrência · Data: Quando aconteceu
  • Seleção: Gravidade — Baixa / Média / Alta / Crítica
  • Texto longo: Descrição detalhada · Upload: Evidência (foto/ficheiro)

8. Boas práticas e resolução de problemas

  • Poucos campos, boas respostas: formulários curtos têm mais submissões — corte o que não é essencial.
  • Obrigatório com parcimónia: marque só o que inviabiliza a resposta se faltar.
  • Placeholders como exemplos: «ex.: 25/09/2026» dentro do campo reduz erros.
  • Teste antes de publicar: crie, construa, submeta uma resposta de teste, e só depois divulgue.
  • Formulários recorrentes: duplique o anterior em vez de reconstruir.
