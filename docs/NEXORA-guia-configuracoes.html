1. O que é a página de Configurações

A página de Configurações é a vista rápida de gestão de utilizadores da organização — lista os membros com os seus papéis e permite criar novos utilizadores diretamente e removê-los. É a versão simples do que a Administração → Utilizadores oferece em profundidade.

Não confundir: «Configurações» (/settings) trata de utilizadores. As definições da organização (SSO, branding, etc.) vivem em Administração → Definições (/admin/settings) — que exige settings.manage. O seu perfil pessoal está em Perfil (/profile).

2. O que a página mostra

ElementoDescrição
Lista de utilizadoresCada membro com avatar, nome, email, cargo e badge com os papéis na organização
Botão «Adicionar utilizador»Abre o formulário de criação
RemoverÍcone de lixeira por membro — com confirmação; não aparece na sua própria linha

3. Criar um utilizador — passo a passo

  1. Configurações → «Adicionar utilizador».
  2. Preencher: Nome, Email (obrigatórios), Cargo (opcional), Função (Admin, Manager, Editor, Member, Viewer) e Palavra-passe — mínimo 12 caracteres.
  3. «Criar utilizador» → a conta entra na organização com o papel escolhido; o formulário fecha e a lista atualiza.
  4. Erros da API (email duplicado, permissão insuficiente) aparecem em alerta vermelho no formulário.
Atenção à escolha do papel: este formulário oferece todas as funções de sistema, mas a API aplica as regras de proteção — criar com papel ≠ Member exige roles.manage (só Admin). Um Manager que tente criar um «Admin» aqui recebe 403 — deve usar Administração → Utilizadores ou convites.

4. Remover um utilizador

  1. Na linha do membro → ícone de lixeira → confirmar.
  2. O membro é removido da organização (soft delete — o histórico fica na auditoria).
  3. A sua própria linha não tem o botão — a API também bloqueia auto-remoção.

5. Exemplos práticos

Exemplo 1 — Entrada rápida de membro

Novo colaborador sem processo de convite: Configurações → Adicionar utilizador → nome, email, papel Member, password temporária forte → partilhar credenciais por canal seguro.

Exemplo 2 — Saída de colaborador

Configurações → lixeira na linha do membro → confirmar → acesso à organização cortado imediatamente (a sessão expira).

Exemplo 3 — Auditoria rápida de papéis

Rever a lista: «há algum Admin a mais?» — os badges mostram os papéis de cada um à primeira vista.

6. Permissões

Ver a lista de utilizadoresusers.readTodos

Editor/Member/Viewer veem a lista (têm users.read) mas as ações falham na API conforme a tabela — a página é essencialmente de consulta para eles.
