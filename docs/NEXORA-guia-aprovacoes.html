1. O que são Aprovações

As Aprovações são os pontos de decisão humana dentro dos Processos (workflows). Quando um processo atinge um passo do tipo «Aprovação», a execução pára e cria uma pendência para o aprovador designado — que decide Aprovar ou Rejeitar. A página de Aprovações é a fila central onde essas decisões se tomam.

2. Como uma aprovação nasce

  1. Um Processo publicado com um passo «Aprovação» é iniciado.
  2. Ao chegar a esse passo, a instância fica «A aguardar aprovação» e cria a pendência.
  3. O aprovador configurado recebe uma notificação «Aprovação necessária» e vê o item na fila.
  4. Ao decidir, o processo continua: Aprovado → passo seguinte; Rejeitado → salta para o passo configurado em «salto de rejeição» (ou termina).

4. Delegar uma aprovação

  1. Na pendência → «Delegar» → escolher outro membro da organização.
  2. A aprovação passa a ser decidida por essa pessoa — o registo mostra «delegado por {nome}».
  3. Não se pode delegar para si próprio nem para o aprovador atual.
Caso de uso: vai de férias e é o aprovador configurado num processo — delegue as pendências no substituto em vez de bloquear os processos.

5. Quem decide — a regra fundamental

A decisão é por ATRIBUIÇÃO, não por permissão global. Só o aprovador designado no passo (ou o delegado, ou o Super Admin) pode aprovar/rejeitar — mesmo um Admin da organização recebe 403 se não for o designado. A permissão approvals.view deixa ver a fila; approvals.manage está ligada à gestão administrativa das aprovações.
PapelVer filaDecidir
Viewer✓ (approvals.view)Só as que lhe são atribuídas/delegadas
Member✓As suas + delegadas (approvals.manage)
Editor / Manager / Admin✓As suas + gestão
Super Admin✓Qualquer uma

6. Exemplos práticos

Exemplo 1 — Aprovação de documento (o fluxo testado)
  1. Processo «Aprovação de documento» publicado → Iniciar.
  2. Instância fica «A aguardar aprovação» no passo 1 → o aprovador recebe notificação.
  3. Aprovador abre Aprovações → Aprovar → o processo continua sozinho (move documento, notifica, termina) e a notificação de pedido é marcada como lida automaticamente.
Exemplo 2 — Rejeição com salto

Num processo com «salto de rejeição» configurado (ex.: voltar ao passo de correção), Rejeitar não mata o processo — redireciona-o para o passo definido.

Exemplo 3 — Delegação antes de férias

Gestor vai estar ausente → abre cada pendência → «Delegar» para o adjunto → o adjunto passa a ver as pendências na sua fila com a etiqueta «delegado por…».

7. Ligações com outros módulos

  • Processos — as aprovações nascem dos passos «Aprovação»; a instância mostra o histórico da decisão.
  • O meu dia — as suas aprovações pendentes aparecem na secção própria, decidíveis ali.
  • Notificações — «Aprovação necessária» ao ser designado; «Aprovação concedida/rejeitada» a quem iniciou o processo.
  • Dashboard — contagem de aprovações pessoais pendentes.
